Smart Parking Management System Requirements Specification — Lab Project (Team of 3) 1. Project Overview A QR-based smart parking management system that lets drivers view real-time slot availability, reserve slots in advance (Pre-Booking) or on arrival (Live Booking), and check in/out using QR codes. Slot status updates propagate to all connected clients in real time. Built using the MERN stack. 2. Core Modules fi  QR-based Entry/Exit — scan QR at gate to check in/out; slot status updates instantly fi  Booking Engine — Pre-Booking (future time window) and Live Booking (immediate use) fi  Admin & Analytics — manage lots/slots, set pricing, view occupancy and reports 3. Functional Requirements fi  User registration and login (driver and admin roles) fi  View real-time slot availability (available / reserved / occupied) per lot fi  Pre-Booking: select a future date and time window; slot becomes 'reserved'; QR code generated fi  Live Booking: select a currently available slot; slot becomes 'occupied' immediately; QR code generated fi  QR scan at entry validates the booking, updates slot status, and logs entry time fi  QR scan at exit marks the slot free, logs exit time, and calculates duration/fee fi  Auto-cancel a pre-booked reservation if the user doesn't check in within a set time window fi  Real-time slot status broadcast to all connected clients on any change fi  Payment calculation based on parking duration (and booking type) fi  Prevent conflicts — a slot cannot be double-booked for an overlapping time window fi  Admin dashboard: add/remove lots and slots, set pricing, view live occupancy and logs/reports fi  Notifications: booking confirmation, reservation expiring soon, payment receipt 4. Non-Functional Requirements fi  Real-time sync between database and all connected clients (Socket.io) fi  No double-booking — enforced via DB-level transaction checks fi  Security: QR codes are single-use and tied to a specific booking ID fi  Response time under ~2 seconds for slot status/availability updates fi  Mobile-responsive UI, since QR scanning happens mainly on phones fi  Scalable to support multiple parking lots and concurrent users 5. Technology Stack (MERN)fi  Frontend: React (+ Tailwind/Material UI), html5-qrcode for scanning fi  Backend: Node.js + Express — REST APIs for booking, auth, admin fi  Database: MongoDB — collections: users, lots, slots, bookings, transactions fi  Real-time layer: Socket.io for broadcasting live slot status fi  QR handling: qrcode (generate) + html5-qrcode (scan) fi  Auth: JWT-based, with driver and admin roles 6. Team & Jira Structure (3 Members) fi  Member A — QR Entry/Exit + Socket.io real-time updates fi  Member B — Booking Engine (Pre-Booking + Live Booking, conflict checks) fi  Member C — Admin Dashboard, Analytics, Authentication fi  Workflow: To Do fi In Progress fi In Review fi Done fi  Sprint length: 1–2 weeks per sprint
